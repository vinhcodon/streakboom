# ADR-0034: The website gets static pages per language, built by a small script, with structured data, `llms.txt` files and no visitor tracking

- **Status:** accepted (decisions); **built and deployed on 2026-11-09** (commit `76a851b`), see the plan for what is still open
- **Date:** 2026-11-09
- **Decided by:** Vinh (author), with Claude (the website session)

## Context
The release prompt of 0.2.5 (ADR-0033) asked the website session for a structure that search engines (SEO) and AI answer engines (GEO) can read. On 2026-11-09 the live site had one page whose English facts were in the HTML but whose version, release notes and all Vietnamese text were filled in by JavaScript, no `robots.txt`, `sitemap.xml`, `llms.txt`, structured data or `hreflang`, and a deploy that did not run when a release changed `CHANGELOG.md`. The proposal and the evidence are in [`../plans/website-seo-geo.md`](../plans/website-seo-geo.md); this record is the author's answer to its seven questions.

## Decision
- **D1 (languages and URLs): B.** Two static pages: `/` in English and `/vi/` in Vietnamese, with `hreflang` (and `x-default` on `/`) and canonical links; the language toggle becomes a plain link.
- **D2 (how pages are produced): B, chosen with the hosting in mind.** The author asked for the option that fits GitHub Pages. GitHub Pages serves only static files (no server code, no per-request redirects or headers); the site is already built by a GitHub Actions job that runs Node. So: a small Node build script in `scripts/` (no framework) fills templates from one source (the strings in `site/i18n.js`, the version from `app/src-tauri/tauri.conf.json`, the notes from `CHANGELOG.md`) and writes plain files that Pages serves as they are (`/vi/index.html`, `/changelog/index.html`, `404.html`, `sitemap.xml`, `robots.txt`, `llms.txt`). `pages.yml` also runs when `CHANGELOG.md`, `updates/latest.json` or `tauri.conf.json` change, so a release redeploys the site.
- **D3 (which pages): B.** Home, changelog and a privacy page (`/privacy/` and `/vi/privacy/`); the home keeps a short privacy summary and the FAQ. The changelog is English only and the Vietnamese pages link to it.
- **D4 (structured data): B.** JSON-LD `SoftwareApplication`, `Person` (the author, `sameAs` GitHub only), `WebSite` and `FAQPage`, generated by the build. No `aggregateRating` or anything else that is not true. No `HowTo` or `BreadcrumbList`.
- **D5 (files for AI engines): C.** `llms.txt` and `llms-full.txt`, generated from the same source.
- **D6 (crawler policy): A.** `robots.txt` allows everything and names the sitemap.
- **D7 (measuring): A.** Google Search Console and Bing Webmaster Tools (verified with DNS TXT records at name.com, no code on the site) and a dated log of the answers of AI assistants to a fixed set of questions. **No analytics script** on the site.

## Alternatives considered
Keeping one page switched by script (Vietnamese stays invisible to crawlers); Vietnamese as the default language (the README, the app and most queries so far are English); Astro (more than a few pages' worth of tooling for a site that is a few pages; kept as the way out if the site grows beyond about six pages); a full split into many pages (more to keep true); analytics (conflicts with the product's privacy promise); blocking AI crawlers (makes wrong answers more likely).

## Consequences
- The build becomes part of the site's contract: it fails, and the deploy does not happen, when the version in the data differs from `tauri.conf.json`, the FAQ in JSON-LD differs from the visible FAQ, an `hreflang` pair is not reciprocal, a page lacks a canonical link or an `h1`, an image lacks `alt`, an internal link is broken, or a retired name or forbidden claim appears (the list is in the plan, section 5).
- The interactive Peak, the favicon and the share image stay as they are; the hero starts Peak after first paint so it cannot delay the page.
- Work order: baseline first (Lighthouse numbers and the assistants' answers, before any change), then data and templates, the English home, the Vietnamese home, the changelog and privacy pages, structured data and the crawler files, verification. See the plan, section 6.
- The author adds the DNS TXT records for the search tools' verification (and GitHub's domain verification); the agent cannot reach name.com.
- `llms.txt` support by search and assistant vendors is unproven; the pages themselves carry the weight.
- The language is now chosen by the address, not by a script: a Vietnamese visitor who opens `/` sees English with a link to `/vi/`. The old script used the browser language and a saved choice; that was dropped on purpose (redirecting by browser language hides one language from crawlers). If it turns out to cost Vietnamese visitors, a small banner "Xem bằng tiếng Việt" can be added without redirecting.
- Built 2026-11-09: `scripts/build-site.mjs` and `scripts/site/` (facts, pages, files, checks, tests), `site/strings.mjs`, the workflow uploading `_site/` and triggering on `CHANGELOG.md`, `updates/latest.json` and `tauri.conf.json`. Not verified: the plan's section 7 (crawler behaviour, rich-result status, Lighthouse numbers, the current ranking), a redeploy caused by a real release, and the rule "a failed check means nothing is deployed" in the real workflow (the checks are unit-tested, the workflow behaviour is not).
