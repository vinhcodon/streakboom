# The website

The static website (streakboom.com) is owned by the website session; the app session does not edit `site/` or `scripts/site/` and tells it what changed through [`handoff/website-release-prompt.md`](handoff/website-release-prompt.md). **This file is the website session's: it is rewritten when the site changes (last checked 2026-11-13).**

## What it is
Static pages with no framework, no bundler, no npm dependency and no third-party script except the measurement tools the author has approved and listed in ADR-0096 (today, when switched on, the Cloudflare Web Analytics script), built by `node scripts/build-site.mjs` (Node 24) into `_site/` and served by **GitHub Pages** (ADR-0034). Every fact is in the HTML, so no script is needed to read it.

| Pages | Addresses |
|---|---|
| Home (install, the promises, features, install steps, **Code signing policy**, FAQ, the newest update) | `/`, `/vi/`, `/ja/` |
| How it works | `/how-it-works/`, `/vi/how-it-works/`, `/ja/how-it-works/` |
| Privacy | `/privacy/`, `/vi/privacy/`, `/ja/privacy/` |
| Stickers (the set in the language of the page; tap to copy, a row of recent stickers) | `/stickers/`, `/vi/stickers/`, `/ja/stickers/` |
| Changelog (English) and its Atom feed | `/changelog/`, `/changelog.xml` |
| Crawler files | `404.html`, `sitemap.xml` (with the sticker images), `robots.txt`, `llms.txt`, `llms-full.txt`, `downloads.json` (the ledger of the download counter) |

The Vietnamese and Japanese texts were written by an AI and have no native reader (Japanese is marked beta). All texts are in `site/strings.mjs`.

## How it is built and deployed
- **Deploy:** `.github/workflows/pages.yml` runs on a push to `main` that touches the site sources, `scripts/build-site.mjs`, `scripts/site/`, the app's rig, `tauri.conf.json`, `CHANGELOG.md`, `updates/latest.json`, the sticker folder `docs/plans/assets/stickers/set-v2/` or the workflow itself, **once a day at 03:17 UTC** (the download counter), and by hand (`gh workflow run pages.yml --repo vinhcodon/streakboom`). It builds and checks first; **if one check fails nothing is deployed and the site stays as it was.**
- **A release redeploys the site by itself** as long as `CHANGELOG.md` has its entry (`## x.y.z (date)` then `- ` lines, the first a short bold sentence). **The release must be published before the build runs:** the Download button is the installer file itself (`releases/download/v<version>/Streakboom_<version>_x64-setup.exe`, ADR-0065) and the Pages build asks GitHub that the release `v<version>` is published (not a draft) and has that file; if not it stops with "there is no published release". Publish the release first; if the push came first, run the workflow again afterwards.
- **Download counter (ADR-0052, ADR-0053):** the number on the home page counts GitHub downloads of the installer (never installs or people); the build reads the releases from the GitHub API and the previous ledger from the live site, keeps a daily history, and publishes `downloads.json`.
- **Stickers (ADR-0051, ADR-0053, ADR-0073, ADR-0075):** pages are built from one folder, `docs/plans/assets/stickers/set-v2/` (`vi/`, `en/`, `ja/` pictures and `manifest.json`, the single source of the words, titles, alt texts, `reviewed` flags, licence and font credits). A tap copies the original 360 px PNG; `?px=NN` copies at another size for tests. The saved and recent stickers are kept in the visitor's browser only, by slug, in one key (ADR-0060, ADR-0073, ADR-0079); Peak's lines after a copy and when nothing is found are in `site/strings.mjs` (`st_lines`, `st_night`, `st_search_none`). The row "Peak's picks" above the grid is Vinh's list in `scripts/site/catalog/popular.json` (ADR-0084; edit the list, nothing else). The sticker tags are given by rules (`scripts/site/catalog/`, ADR-0077) and feed the **search** of the sticker pages (`site/search.js`, `site/normalize.js`, two index files by script, `assets/stickers/search-latin.json` and `search-ja.json` (the search is by meaning in any language on any page, ADR-0082), built by `scripts/site/search-index.mjs`); the page Vinh skims is `docs/plans/sticker-tags-proposed.md`, generated by `node scripts/site/tags-report.mjs`.
- **Language:** each language has its own address with reciprocal `hreflang` and an English `x-default`; a thin dismissible suggestion strip offers the page in the browser's first language the site has (ADR-0067); no redirect, no IP, no location.
- **Code signing policy (ADR-0076):** the home page says honestly that nothing is signed yet; the SignPath attribution line is added only when the author says the project is approved.
- **The build checks** (`scripts/site/checks.mjs`, more than a hundred tests in `scripts/site/*.test.mjs`): the version everywhere against `tauri.conf.json` and the newest `CHANGELOG.md` entry; the FAQ in the structured data against the visible FAQ; `hreflang`, canonical links, one `h1`, `alt` text, internal links, the sitemap; the facts in the static HTML; the numbers and phrases of the README (263 hand-written lines, the memory and processor ranges, "just under its feet", the five promise sentences); retired and outdated wording, unbacked claims, health claims, the word "lonely" and streaks, a code-signing promise, the SignPath attribution before approval; the size budget; the sticker set against its manifest; the sticker tags; the Code signing policy section; the Download link. **If you change a sentence of the README that the build checks, tell the website session.**

## Where to edit
The text of the three languages in `site/strings.mjs` (the build fails if a language lacks a key or a placeholder, or a string is unused); the page layouts, structured data and crawler files in `scripts/site/` (`pages.mjs`, `files.mjs`, `checks.mjs`, `stickers.mjs`, `catalog.mjs`, `downloads.mjs`, `assetversion.mjs`: the hash in the addresses of the stylesheet and scripts, ADR-0087; `counting.mjs` and `worker/`: the counter of sticker copies, off until its address is in `catalog/counting.json`, ADR-0092); the style in `site/style.css`; the scripts in `site/app.js`, `site/peak.js`, `site/stickers.js`.

## Peak on the page is the app's own cat
The build turns `app/src/lib/rig/*.ts` into browser JavaScript in `site/peak/` (generated, git-ignored), so the page cannot drift from the app. Needs Node 22.13 or newer. For that the three rig files may only use TypeScript syntax that can be erased (no `enum`, `namespace` or constructor parameter properties) and may import only each other (`import type` from `../sprites.ts` is fine); a test in `app/src/lib/rig.test.ts` checks it. The interactive Peak follows the pointer, plays a short tour and stops when you touch the page.

## Preview and tools
- **Preview:** `node scripts/site-dev.mjs`, then open `http://localhost:4173`. It builds like the deploy (without the download counter or the release check) and rebuilds on every page request; a failed check is shown as text.
- **Live build on your machine:** `STREAKBOOM_DOWNLOADS=live node scripts/build-site.mjs` (with a `GITHUB_TOKEN` to lift the rate limit) reads GitHub like the workflow does.
- **Icons and share image:** with the preview running, open `http://localhost:4173/__gen` and press Save all. It redraws `site/assets/` (favicon, touch icon, header logo, share image) and `assets/peak-icon-1024.png` from the rig. The sticker share picture `site/assets/sticker-preview.png` is a copy of a collage made by the sticker session.

## Domain and previews
- **Domain:** `streakboom.com` (registered at name.com). DNS: four `A` records (185.199.108.153, .109.153, .110.153, .111.153) and four `AAAA` records (2606:50c0:8000::153 to 8003::153) for the root, and a `CNAME` for `www` to `vinhcodon.github.io`. The custom domain and Enforce HTTPS are set in the repository's Settings, Pages. `www`, `http` and the old `vinhcodon.github.io/streakboom` address redirect to `https://streakboom.com/`.
- **Share previews:** Facebook and Zalo cache the title and image of a link. After changing `site/assets/og-image.jpg`, `site/assets/sticker-preview.png` or a page title, press Scrape Again in the Facebook Sharing Debugger.
